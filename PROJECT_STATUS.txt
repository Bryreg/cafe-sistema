================================================================================
CAFE-SISTEMA: PROJECT SUMMARY & VISION
================================================================================

PROYECTO
--------
Sistema de gestión integral para cafetería con:
- POS (punto de venta) para registrar ventas
- Gestión de turnos por baristas (responsabilidad colectiva)
- Control de inventario con FIFO y stock negativo permitido
- Cuadratura de caja diaria
- Dashboard admin para reportes y auditoría

STACK TÉCNICO
-------------
Backend:  FastAPI 0.115, SQLAlchemy 2.0, SQLite (dev) / PostgreSQL (prod)
Frontend: React 18.3, TypeScript 5.4, Vite 5.2, TailwindCSS 3.4, React Router 6.23
Deploy:   Render (backend) + Cloudflare Pages (frontend). LA RAMA PRINCIPAL ES
          `develop` — ver DEPLOY.md seccion 1, que es la fuente de verdad.
          (Este archivo decia "frontend, rama main": `main` es un archivo
          historico con historia DISJUNTA, no produccion. Ver DEPLOY.md.)

FLUJO DE USUARIO (BARISTA/KIOSK)
================================================================================

1. Abre navegador del café → KioskSetup
2. Ingresa PIN (2026 actualmente) + Sede ID (2) → "Activar dispositivo"
3. Redirige a POS (landing page)
4. Tabs: POS activo, "Turno" a un lado
5. Click "Turno" → GestionTurno
6. Si no hay turno: "Abrir turno"
   a) Elige tipo: Apertura / Intermedio / Cierre
   b) Selecciona baristas que estarán en turno
   c) Ingresa base de caja ($)
   d) Confirma → turno abierto
7. Con turno activo:
   - Ve baristas en turno (pills)
   - Ve ventas del día (total, efectivo, tarjeta)
   - Accede a flujo: Conteo apertura → Cuadre llegada → Conteo cierre → Entrega

================================================================================
FLUJO DE USUARIO (ADMIN)
================================================================================

1. Abre navegador en PC (o en café)
2. Navbar KioskSetup: link "Admin →"
3. Ruta /admin-login
4. Selecciona usuario (tipo admin)

6. Redirige a /dashboard (AdminHub)

================================================================================
DECISIONES ARQUITECTÓNICAS CLAVE
================================================================================

1. Turno como unidad de responsabilidad (no barista individual)
   → Refleja realidad: baristas comparten caja durante turno
   → Simplifica auditoría: "quién fue responsable" = "todo el turno"

2. Kiosk user es un usuario real en DB (no special case)
   → Mismo JWT flow que barista autenticada
   → Simplifica permisos: kiosk_user.rol = "barista"
   → 10-year JWT: no re-login en kiosco (vs yearly tokens en admin)

3. Negative stock permitido (post-entry)
   → Realidad del café: venden primero, compran después
   → FIFO consume real, negativo es deuda de entrada
   → Simple: no hay "hold" ni "reservation", solo movimientos

4. Real-time = 8s polling (no WebSocket)
   → Kiosco + PC comparten mismo endpoint público
   → Escala sin infrastructure compleja
   → Trade-off: 8s de latencia aceptable para POS

5. Desktop-first, mobile-compatible
   → POS + Turno tabs usan same width (no sidebar, responsive)
   → Barista puede atender en PC y consultar en phone
   → Admin full desktop (complex dashboards)
